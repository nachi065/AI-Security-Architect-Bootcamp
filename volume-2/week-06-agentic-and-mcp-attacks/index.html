    Week 6: Agentic and MCP attacks¶

    Volume 2 · Weeks 5-6: RAG, agentic and MCP attacks

    You will be able to: threat-model an agent's tools, memory and identity, test for the main agentic failures, and map findings to the Agentic Top 10.

    Plan agent tests as a tree. Each branch is a test you can run and measure.

    Core concepts

    The curriculum lists these agentic attack areas. Learn each as a pattern, then find it in your own agent.

    • Goal hijacking. Injected content changes what the agent is trying to do.
    • Tool misuse and excessive agency. The agent uses a legitimate tool in a harmful way, or has tools and permissions it never needed.
    • Tool-description poisoning. In MCP and similar systems, the model reads tool names and descriptions as instructions. A malicious or compromised server can place hostile instructions there.
    • Memory poisoning. Content written into long-term memory persists across sessions and influences later behaviour.
    • Identity and privilege abuse. The agent acts with credentials broader than the task, or confuses whose authority it is acting under (the "confused deputy" problem).
    • Inter-agent trust abuse. Agents trust each other's messages by default, so one compromised or spoofed agent steers the rest.
    • Cascading failures and rogue agents. One error or compromise propagates through chained steps, or an agent keeps acting beyond its intended bounds.

    Study plan (about 9 hours)

    1. Read the OWASP Top 10 for Agentic Applications 2026 in full, about 2.5 hours. Confirm on the OWASP site that you have the current version.
    2. Read the MCP documentation sections on security and authorisation, plus two independent security write-ups on MCP risks, about 2 hours.
    3. Lab and deliverable, about 4.5 hours.

    Guided lab: red-team your agent and MCP server

    1. Scope: your Volume 1 agent and its MCP server, locally. Out of bounds: any real account or external service.
    2. Draw an attack tree with "agent performs an unauthorised action" at the root, and branches for each path you will try (hijack via retrieved document, tool-description poisoning, over-broad tool, memory write).
    3. Hijack test. Plant instructions in a document the agent retrieves and measure how often the agent changes its action.
    4. Tool-description test. Edit your own MCP server's tool description to include a hostile instruction and see whether the agent obeys. This is a test of your own server, not of anyone else's.
    5. Privilege test. List what your agent's identity can do versus what its task needs. Show one action it can perform that it should not.
    6. Approval test. Try to make the human-approval prompt misleading and note whether a reviewer would catch it.
    7. Map every confirmed finding to an Agentic Top 10 category.

    Deliverable (commit to v2-week06/): the attack tree and a set of mapped findings in the standard template.

    Self-check

    1. Why can a tool description be an attack vector?
    2. What is the confused-deputy problem in an agent?
    3. How does memory poisoning differ from a one-time prompt injection?
    4. Name two reasons a human-approval step may fail.
    5. Which single design change would most reduce harm if the agent is hijacked?
