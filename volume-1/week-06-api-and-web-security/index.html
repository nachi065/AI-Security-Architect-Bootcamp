    Week 6: API and web security¶

    Volume 1 · Part 3 (Weeks 6-9): APIs, containers, Kubernetes and cloud for AI

    Part goal

    learn how AI services are attacked and deployed in practice, using the Week 5 API as your running subject.

    You will be able to: find and fix common API vulnerabilities and write them up as pentest-style findings.

    Core concepts

    • REST and HTTP semantics. Methods, status codes, headers, cookies, CORS.
    • Authentication and authorisation. OAuth 2.0 and OpenID Connect at the level of roles and flows (authorization code flow with PKCE is the standard for user-facing apps). Authentication says who you are; authorisation says what you may do. Mixing them up causes most API bugs.
    • JWT pitfalls. Unvalidated signatures, accepting the none algorithm, missing expiry checks, weak signing secrets, trusting claims without verifying the issuer and audience.
    • OWASP Top 10 and OWASP API Security Top 10. Focus on broken object-level authorisation (BOLA), broken authentication, excessive data exposure, injection and server-side request forgery (SSRF). Check the current edition of each list on the OWASP site.
    • Intercepting proxies. Burp Suite Community or OWASP ZAP let you see and modify requests between a browser or client and a server.

    Study plan (about 9 hours)

    1. OWASP API Security Top 10 and the matching Cheat Sheets, about 3 hours.
    2. OAuth 2.0 and OIDC explainer from a reputable vendor-neutral source, about 2 hours.
    3. Lab and deliverable, about 4 hours.

    Guided lab: attack and fix a vulnerable API

    1. Run an intentionally vulnerable target locally in Docker: OWASP Juice Shop or crAPI (follow the project's current README). Never expose it to the internet.
    2. Proxy traffic through Burp or ZAP. Map the endpoints.
    3. Find at least three issues. Good candidates: BOLA (change an object ID to read someone else's data), weak authentication, excessive data in responses.
    4. For each: reproduce it, capture evidence (request, response, screenshot), rate the severity with a stated reason, and describe the fix.
    5. Apply the same checks to your own Week 5 API and fix what you find.

    Deliverable (commit to week06/): three findings in a consistent format: title, severity, description, steps to reproduce, evidence, impact, remediation.

    Self-check

    1. What is BOLA and why is it so common?
    2. Name three JWT validation mistakes.
    3. What is the difference between authentication and authorisation? Give an API example of each failing.
    4. How does SSRF work, and why is it especially dangerous in cloud environments?
    5. Why should an LLM-backed API still enforce object-level authorisation?
